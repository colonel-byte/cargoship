ZarfClusterAgeEncryption

records the age recipients a document’s credentials were encrypted to.

PropertyTypeRequiredDefaultDescription
lastModifiedstringnois when cargoship last rewrote the credentials in this document, in RFC 3339.
recipientsarray of stringnolists the age public keys cargoship encrypted to, in the order they were given. An SSH key keeps its authorized_keys comment, since that is the part that says whose key it is.

ZarfClusterConfig

holds cluster-wide configuration.

PropertyTypeRequiredDefaultDescription
loadbalancerstringyesis the hostname clients use to reach the cluster control plane.
profilesmap[string]ZarfClusterProfilesnomaps a profile name to host and engine overrides that a host can select.
registriesarray of ZarfClusterRegistriesnolists the container registries the cluster uses.
valuesobjectnooverrides the values the distro package was built with. It is the same
nested structure the package ships, addressed by the same dotted paths, and it
must still satisfy the package’s values schema. Keys the package does not
define are kept, so a cluster can carry values a later package version reads.

ZarfClusterEncryption

records how the credentials in a document were encrypted.

PropertyTypeRequiredDefaultDescription
ageZarfClusterAgeEncryptionnorecords the age recipients this document’s credentials were encrypted to. Nothing verifies this list and nothing can: an age header carries no recipient identifier, so editing it changes what the file claims and not a byte of what it holds.

ZarfClusterMetadata

holds identifying information for a cluster.

PropertyTypeRequiredDefaultDescription
encryptionZarfClusterEncryptionnorecords how the credentials in this document were encrypted. Cargoship writes it and never reads it back as key material, because an age header names no recipient: this records what was done, not a fact anything can check against the ciphertext beside it.
namestringyessets the cluster name. If you allow cargoship to update the kubeconfig, cargoship uses this name there.

ZarfClusterProfiles

holds the host and engine overrides for one profile.

PropertyTypeRequiredDefaultDescription
concurrencystring or integernolimits how many hosts using this profile cargoship processes at once, e.g.
draining, upgrading, initializing, or uninstalling. It accepts a fixed count (“1”) or a
percentage of the hosts sharing this profile (“25%”). Empty falls back to the phase’s
default concurrency.
engineZarfHostEnginenoholds the node label and taint overrides applied to a host that selects this profile.
hostZarfHostConfignoholds the configuration overrides applied to a host that selects this profile.

ZarfClusterRegistryTLS

holds the TLS connection settings for a container registry.

PropertyTypeRequiredDefaultDescription

an Ansible Vault-encrypted string, which cargoship decrypts at apply time.

keyFilestringnois the path on the host to the client private key used to authenticate to the registry.

ZarfFirewallRule

is a single backend-neutral firewall rule.

PropertyTypeRequiredDefaultDescription
actionstringyesis what cargoship does with traffic that matches the rule. One of allow, deny, reject.
destinationstringnois the address or CIDR the traffic goes to.
directionstringnoinselects which traffic the rule matches. It defaults to in. One of in, out, forward.
egressstringnonames where forward traffic leaves. It is a zone on firewalld hosts and an
interface on ufw hosts. It applies to forward rules only.
ingressstringnonames where forward traffic enters. It is a zone on firewalld hosts and an
interface on ufw hosts. It applies to forward rules only.
namestringnoidentifies the rule. Cargoship uses it to name the artifacts it writes on the
node, so it must be unique within a host. Cargoship generates one when it is empty.
portstring or integernois the port number, or inclusive port range, the rule matches.
protocolstringnois the type of traffic the rule matches. One of tcp, udp, sctp, dccp.
sourcestringnois the address or CIDR the traffic comes from.
