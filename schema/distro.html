Rendered from schema/zarf-v1alpha1-distro-package-schema.json.

FileSource

records where one file in the package was actually read from, for a file whose declared source a –file-override redirected.

PropertyTypeRequiredDefaultDescription
declaredstringyesis the source the distro definition named.
overridestringyesis the Source prefix of the override that matched, which is the one that won
when several could have.
pathstringyesis where the file was staged inside the package, for example “files/0/k3s”. It
identifies the entry even when several files share a declared source.
resolvedstringyesis where cargoship read the bytes from instead: a mirror URL, or a path on
the build host.
shasumstringyesis the checksum the bytes were verified against. An override is refused for a
file that declares none, so this is never empty.

ZarfDistroBuildData

holds information recorded when the package was built.

PropertyTypeRequiredDefaultDescription
architecturestringnois the CPU architecture used to build the package. Populated only when the package targets a single architecture. One of amd64, arm64, riscv64.
architecturesArchesnolists the CPU architectures used to build the package.
fileOverridesmap[string]stringnomaps each source URL prefix to the mirror or local directory files were
downloaded from instead. Like RegistryOverrides, this is the configuration the build was
given. For what each override actually did, see FileSources.
fileSourcesarray of FileSourcenorecords every file whose source an override redirected: what the definition
declared, where the bytes were read from instead, and the checksum they were verified
against. It is empty for a build that used no overrides, so a package built without them
is unchanged. Entries are in the order the files were staged, which is the order they
appear in the definition, so a reproducible build still produces identical output.
provenanceFilesarray of stringnolists files in the package that checksums.txt does not cover.
These are files added after cargoship generates checksums, for example signature files.
The signed distro.yaml authenticates this list.
registryOverridesmap[string]stringnomaps each original registry to the registry actually used to build the package.
reproduciblebooleannoindicates Build.Timestamp was pinned to a fixed value
(config.Timestamp) instead of the actual build time, so identical
package inputs produce byte-identical output.
signedbooleannoindicates whether the package was signed. A nil value means the signing status was not recorded.
timestampstringnois the time the package was created.
versionstringnorecords the distro version used to build the package.

ZarfDistroValues

declares the values a package ships with.

PropertyTypeRequiredDefaultDescription
filesarray of stringnolists the YAML values files cargoship merges, in order, to build the package’s default values. Each entry is a path relative to the package definition, an absolute path, or a URL. A later file overrides an earlier one, key by key.
mappingsarray of ZarfDistroValueMappingnoproject values onto the engine configuration, so that one value a
cluster sets reaches wherever the distro needs it. Each mapping reads the
source path out of the resolved values and writes it to the target path,
which is relative to spec.config.engine. A source the values do not define
is left alone, so the package’s own engine configuration stands as the
default.
schemastringnois the JSON Schema document the merged values must satisfy. Cargoship checks the values against it when it builds the package, and refuses to build when they do not match. The schema must not use $ref.

ZarfFile

defines a file shared by the distro and cluster APIs.

PropertyTypeRequiredDefaultDescription
datastringnoholds the inline file content.
executablebooleannosets executable permissions on the file when true.
extractPathstringnois the path cargoship extracts from a tarball.
groupstringnois the group that owns the file.
isDirectorybooleannoindicates that Target is a directory. Cargoship uses this mainly for image uploads.
namestringnoidentifies the file entry. It is not the file name on disk.
permanynosets the permissions cargoship applies to the file. It accepts an octal string or an integer, for example “0644” or 644.
selectorBinarySelectornocontrols whether cargoship uploads this file to a given node.
shasumstringnoverifies the file when cargoship sources the distro package.
sourcestringyesis the path where cargoship finds the file when it creates the package.
symlinksarray of stringnolists the symlinks cargoship creates that point to Target.
targetstringyesis the path on the remote host where cargoship writes the file.
templatebooleannorenders the file’s contents as a Go template against the package’s values before cargoship uploads it. It defaults to false, because most files are binaries or archives that a template pass would corrupt.
userstringnois the user that owns the file.
